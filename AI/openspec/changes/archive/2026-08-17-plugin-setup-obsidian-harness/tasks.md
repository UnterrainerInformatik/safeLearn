**Also found here, and it changed the design:** the AppImage is only a launcher. Obsidian updates itself by writing a newer `.asar` into its application data and loading that, so 1.11.4 launches and **1.13.7 runs**. The renderer exposes neither `app.appVersion` nor a global `apiVersion` to an evaluate, so the reported version is read from the `.asar` that got loaded, with the user-agent as fallback.

**Also decided here:** the application-data directory is the one thing *not* rebuilt per run. A fresh one makes Obsidian download its current release (8.7 MB) before it will start.

- [x] 4.5 Expose typing into a document through the protocol's lowest-level input, not by setting document state — the defect being hunted is one that appears while editing (design Risks). — `page.keyboard.type` with a delay, plus `placeCursorAfter` to put the cursor where a person would.
- [x] 4.6 Write a screenshot on failure into `test/.runtime/`, named for the check that failed. Follow whatever the existing harness does for its own failure screenshots. — A `watched(name, body)` wrapper in the suite catches, screenshots and appends the path to the failure message, the way the server harness does for a failed login.

**Found while writing 4.4, and it is the single most important thing about this harness:** both of Obsidian's renderers are **virtualized**. The editor keeps only the lines around the viewport in the document; the reading view renders sections as they are approached. A decoration on line 157 exists in CodeMirror's decoration set and has no element to find. The first five checks failed for exactly this reason and looked like "the plugin did nothing". `reveal(container, needle)` scrolls the target into view first, and every check that asserts about a specific tag calls it. Without this the harness cannot tell "not decorated" from "not on screen".
